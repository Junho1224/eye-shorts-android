# EyeShorts 0.1.6 — 눈·입으로 쇼츠·릴스 제어

Android 8.0(API 26) 이상용 실험 앱입니다. 전면 카메라의 눈·입 특징점을 분석하여 기존 Android YouTube 쇼츠와 Instagram 릴스에서 위/아래 스와이프와 재생/일시정지용 중앙 탭을 보냅니다.

**설치 파일:** [GitHub 릴리스에서 EyeShorts 0.1.6 APK 받기](https://github.com/Junho1224/eye-shorts-android/releases/tag/v0.1.6)

네 가지 눈 입력 방식에 **입 벌리기 → 영상 재생/일시정지**를 함께 사용할 수 있습니다. 윙크 모드는 오른쪽 눈 감음 → 다음 영상, 왼쪽 눈 감음 → 이전 영상으로 즉시 한 번 입력합니다. 0.1.4의 실제 다음 넘김은 사용자에게 긍정적인 피드백을 받았습니다. 새 입 벌림 감지와 실제 재생/일시정지 전환, 좌우 구분·이전 넘김·Instagram 호환성은 실기기 확인이 필요합니다.

## 설치와 첫 테스트

1. [릴리스 페이지](https://github.com/Junho1224/eye-shorts-android/releases/tag/v0.1.6)의 **EyeShorts-0.1.6-debug.apk** 하나를 휴대폰에서 내려받아 설치합니다. 로컬 빌드 결과는 `dist/`에 생성됩니다. 기존에 제공한 APK와 같은 개발용 키로 서명하여 업데이트 설치할 수 있습니다.
2. **넘기는 방법 → 한쪽 눈 윙크 → 윙크 연습하기**를 선택합니다. 카메라 권한을 허용하고 필요하면 알림도 허용합니다.
3. 미리보기에서 얼굴과 눈이 보이는지 확인합니다. 인식한 홍채에는 점이 표시되며 ‘얼굴 인식 중 · 양쪽 눈 뜸’, ‘한쪽 눈 감음’, ‘얼굴 위치 조정 필요’ 등의 상태가 표시됩니다.
4. **본인의 오른쪽 눈을 감으면 다음 영상**, **왼쪽 눈을 감으면 이전 영상**으로 인식합니다. ‘한쪽 눈 감음’과 동일한 기준으로 즉시 한 번 입력합니다. 미리 눈 뜸을 학습하거나 0.4초 유지하거나 다시 뜰 때까지 기다리는 조건은 없습니다.
5. 연습 화면의 **다음 N · 이전 N · 재생/멈춤 N**이 올라가는지 확인합니다. 다음 입력 전에는 양쪽 눈을 뜬 뒤 약 2초 간격을 두고 다시 한쪽 눈을 감습니다. 연습에서는 실제 스와이프나 탭을 보내지 않습니다.
6. **접근성 연결 설정**에서 쇼츠·릴스 및 다음/이전 제어 안내에 동의한 뒤 Android 접근성 설정에서 **EyeShorts · 눈으로 넘기기**를 켭니다. 이전 버전에서 동의했어도 이번 범위 안내는 한 번 더 표시합니다. 이미 켜져 있으면 앱으로 돌아옵니다.
7. **눈으로 넘기기 시작 → 유튜브 열기 또는 인스타그램 열기**를 누르고, 해당 앱에서 **쇼츠 또는 릴스를 전체 화면**으로 재생합니다. 오른쪽 눈은 위로, 왼쪽 눈은 아래로 스와이프합니다.

한 번 추적을 시작하면 두 앱 사이를 전환해도 사용합니다. 릴스에서 ‘릴스 재생 화면을 확인하지 못했어요’가 나오면 전체 화면 릴스인지 확인합니다. Instagram 버전에 따라 알려진 화면 ID가 달라 인식되지 않을 수 있으며, 이 경우 실제 기기의 추가 확인이 필요합니다. 업데이트 후 인스타그램 이벤트를 받지 못하면 Android 접근성의 EyeShorts를 껐다 켠 뒤 앱에서 다시 시작합니다.

윙크의 눈 감음 판정은 화면 상태와 같은 `FaceQuality.ONE_CLOSED`를 사용합니다. 한쪽 눈을 계속 감거나 감는 쪽을 바꿔도 반복 입력하지 않으며, **양쪽 눈 뜸**이 확인되어야 다음 입력을 받습니다. 입력 사이에는 기존 스와이프 제한과 같은 1.8초 대기 시간이 있습니다. 대기 중 감았다면 양쪽 눈을 뜬 뒤 다시 감습니다. 성공 문구는 약 1.2초 유지합니다.

단일 상태로 즉시 판정하므로 깜빡임 도중 잠깐 ‘한쪽 눈 감음’으로 측정된 경우도 입력에 포함됩니다. 양쪽 눈 감음 자체, 얼굴을 찾지 못한 상태, 여러 얼굴, 얼굴 크기/자세가 부적합한 상태에서는 입력하지 않습니다. 카메라 미리보기 확인 모드는 입력을 보내지 않으며, 실제 추적은 YouTube 쇼츠 또는 Instagram 릴스 재생 화면이 확인될 때만 작동합니다.

미리보기만 확인하려면 **카메라 미리보기 켜기**를 누릅니다. 눈과 입의 인식 상태를 표시하며 입력 명령을 보내지 않습니다. 카메라 확인/연습/보정 중 앱을 벗어나면 카메라가 종료됩니다. 실제 추적과 5분 관찰은 사용자가 시작한 카메라 포그라운드 서비스로 동작합니다.

종료는 앱이나 알림의 **종료**를 사용합니다. 일시정지도 카메라를 해제합니다. 화면을 끄거나 최근 앱 목록에서 앱을 닫으면 종료되며 자동 재시작하지 않습니다.

## 입 벌리기로 재생·일시정지

홈 화면의 **입으로 재생·일시정지 → 입 벌리기 제어 사용**은 기본으로 켜져 있습니다. 어느 눈 입력 방식과도 함께 사용하며, 이 설정을 끄면 기존 눈 입력만 동작합니다. 설정은 저장되며 추적 중에도 바꿀 수 있습니다.

1. **입 벌리기 연습**을 누릅니다. 시선 위치 보정 없이 입 동작만 확인하며 실제 영상은 제어하지 않습니다.
2. 입을 자연스럽게 벌려 **약 0.3초** 유지합니다. ‘입 벌림 감지’ 후 **입 인식 성공** 횟수가 증가하는지 확인합니다.
3. 계속 벌리고 있어도 한 번만 인식합니다. 입을 닫았다 다시 벌리면 다음 입력을 받습니다. 눈 입력과 합쳐 약 2초 간격을 둡니다.
4. **눈으로 넘기기 시작** 후 쇼츠·릴스의 전체 화면에서 같은 동작을 하면 영상 중앙에 짧은 탭을 보냅니다. 재생 중이면 멈추고, 멈춘 영상에는 같은 동작으로 재생을 요청합니다.

영상이 멈춰도 카메라 추적은 계속하여 입을 다시 벌리는 동작을 받을 수 있습니다. 카메라까지 끄려면 앱이나 알림에서 일시정지 또는 종료합니다.

입 벌리기를 인식하는 동안에는 눈 넘김 입력을 잠시 억제합니다. 입을 닫고 양쪽 눈을 뜨면 눈 입력을 다시 받습니다. 같은 대기 시간 안에 시도한 다른 명령은 나중에 지연 실행하지 않으므로, 입이나 눈을 원래 상태로 되돌린 뒤 다시 시도합니다.

입 모양은 입술 안쪽 간격을 입 너비로 나눈 값으로 판단합니다. 말하거나 하품할 때도 같은 입 모양이 유지되면 입력으로 잡힐 수 있으므로 필요할 때 홈의 체크를 꺼둘 수 있습니다.

재생/일시정지는 대상 앱의 중앙 탭 동작을 이용합니다. **실제 영상 상태를 읽거나 저장하지 않으며 ‘탭 완료’는 Android 제스처 완료를 뜻합니다.** 설치된 앱에서 중앙을 손으로 한 번 탭해 멈춤·재생이 전환되는지 먼저 확인할 수 있습니다. 해당 앱 버전에서 탭이 다른 기능을 하면 입 명령도 그 동작을 따르므로 기기별 확인이 필요합니다.

## 네 가지 입력 방식

| 방식 | 준비 | 동작 |
|---|---|---|
| 한쪽 눈 윙크 | 보정·눈 뜸 학습 없음 | 오른쪽 눈 → 다음 / 왼쪽 눈 → 이전, 감음 감지 즉시 한 번 |
| 오른쪽 보기 → 중앙 | 중앙 점 → 오른쪽 점을 각각 약 3초 보정 | 오른쪽을 약 0.3초 본 뒤 중앙으로 돌아옴 |
| 아래 → 위로 눈 움직이기 | 아래쪽 점 → 위쪽 점을 각각 약 3초 보정 | 중앙을 본 뒤 아래쪽을 잠깐 보고 빠르게 위로 이동 |
| 위쪽을 잠깐 응시하기 | 중앙 점 → 위쪽 점을 각각 약 3초 보정 | 중앙을 본 뒤 위쪽을 기본 0.9초 응시 |

응시 시간은 응시 모드에서 0.6–1.8초로 조절합니다. 세 시선 방식은 두 앱에서 다음 영상으로만 넘기며, 인식 후 중앙으로 돌아와야 합니다. 모든 방식에 반복 입력 대기 시간이 있습니다. 윙크는 다음 입력을 위해 양쪽 눈을 다시 뜨면 됩니다.

보정 중에는 표시된 점을 가만히 바라보고, 보정 후 연습에서 명령 동작을 합니다. **‘보정 미완료’는 아직 연습 단계에 들어가지 않은 상태**입니다. 미리보기와 인식 상태를 확인하고 다시 보정합니다.

방식별 준비 방법과 보정 값은 분리되어 있습니다. 기존 선택은 유지하며 선택 기록이 없는 경우 윙크를 기본값으로 사용합니다. 보정 화면 배치가 달라져 0.1.1 이전 시선 보정 값은 재사용하지 않습니다. 윙크는 이 시선 위치 보정이 필요 없습니다.

## 20회 입력과 5분 관찰

홈 화면의 **방식 비교 테스트**에서 선택한 방식의 기록을 만들 수 있습니다.

- **20회 입력 테스트:** 사용자가 동작을 20회 시도한 뒤 연습 화면의 **20회 시도 완료 · 결과 저장**을 누릅니다. 감지 횟수와 얼굴 확인 비율을 기록합니다. 눈 방식만 비교하려면 입 제어를 끄고 시험합니다. 입 제어가 켜져 있으면 입 명령도 감지 합계에 포함됩니다. 시도 횟수 20회는 사용자가 확인하는 값이며 감지 횟수는 실제 정확도나 개별 시도의 정답이 아닙니다.
- **쇼츠·릴스에서 5분 오작동 관찰:** 고의로 명령하지 않고 평소처럼 쇼츠 또는 릴스를 봅니다. **실제 스와이프나 탭을 보내지 않고** 다음/이전/재생·일시정지 명령 감지 횟수의 합계를 기록합니다. 두 앱의 재생 화면이 확인되는 동안의 카메라 측정 시간만 누적하며 다른 화면으로 이동하거나 영상 분석이 끊긴 시간은 제외합니다. 저장 결과는 앱별 구분 없이 입력 방식별 합계입니다.
- 5분 관찰이 완료되면 카메라를 끄고 결과를 저장합니다. 중간에 종료한 불완전한 관찰은 비교 결과로 저장하지 않습니다.
- 얼굴 확인 비율이 낮으면 감지 0회여도 의미가 부족할 수 있습니다. 80% 미만은 실험용 기준으로 ‘재측정 권장’을 표시합니다.
- 입력 방식별 최신 20회 테스트와 5분 관찰 결과를 홈 화면에 표시합니다.

## Android 설치 제한

외부 APK 설치 시에는 APK를 여는 파일 앱의 설치 출처 허용이 필요할 수 있습니다. 접근성이 ‘제한된 설정’으로 막히면 앱 출처를 확인한 뒤 Android 앱 정보에서 **제한된 설정 허용** 항목을 확인합니다. 삼성의 보안 위험 자동 차단이나 회사 관리 정책으로 설치가 제한될 수도 있습니다. 이 APK는 Play Store에 배포된 앱이 아닙니다.

## 범위와 한계

- 정식 Android YouTube(com.google.android.youtube)와 Instagram(com.instagram.android)을 대상으로 합니다. Instagram Lite, 브라우저, 변형 앱은 포함하지 않습니다.
- 전체 화면 쇼츠/릴스 재생 영역 ID와 크기를 확인하고, 제스처를 보내기 직전에 활성 앱을 재확인합니다. 다른 앱·잠금 화면·가로 화면·입력란에 포커스가 있는 상태에서는 보내지 않습니다. 일반 피드·메시지·스토리의 보통 요소 ID는 재생기로 인정하지 않습니다.
- 두 앱의 화면 구조는 공개된 고정 API가 아닙니다. 알려진 ID가 확인되지 않으면 동작하지 않도록 제한합니다. 실제 앱 버전에서 홈 피드·댓글 창·스토리·메시지와 재생 화면을 구분하는지 실기기 확인이 필요합니다.
- 이전 영상은 아래로 스와이프하는 앱의 기본 동작을 사용합니다. 목록의 맨 처음이거나 앱이 이전 항목을 유지하지 않는 경우에는 돌아갈 영상이 없을 수 있습니다. 시청 기록이나 영상 파일을 별도로 저장하지 않습니다.
- 홍채/눈꺼풀/눈 끝점에 기반한 규칙으로 입력을 분류합니다. 전용 아이트래커처럼 화면의 정확한 픽셀 좌표를 측정하는 기능이 아닙니다.
- 눈을 감았을 때는 홍채 위치가 불안정할 수 있어 윙크는 별도의 눈꺼풀 열림 신호를 사용합니다. 조명, 눈의 모양, 카메라 해상도, 안경 반사와 머리 움직임에 영향을 받을 수 있습니다.
- 미리보기의 점과 상태는 모델 추정값을 보여주며 정확한 정답을 보증하지 않습니다.
- 제스처 완료 횟수는 Android의 스와이프/탭 완료 콜백 횟수입니다. 실제 영상 전환이나 멈춤·재생 상태를 검증한 횟수가 아닙니다.

## 데이터 처리

- 카메라 프레임은 메모리에서만 분석하고 해제합니다. 미리보기도 메모리에서만 표시하며 녹화/이미지 저장/전송 기능은 없습니다.
- 미리보기는 화면이 보일 때만 생성합니다. 표시용 한 프레임과 대기용 한 프레임만 유지하고 이전 프레임은 해제합니다. 화면 이탈·추적 종료 시 미리보기도 해제합니다.
- 모델은 APK에 포함하며 병합된 Manifest에서 인터넷 권한을 제거합니다.
- 접근성은 활성 앱의 패키지 이름과 두 앱의 요소 ID·위치·표시 여부 및 입력란 포커스만 확인합니다. 글 내용이나 스크린샷을 읽거나 보관하지 않습니다.
- 입력 방식, 입 제어 켜기/끄기, 보정 수치, 응시 시간, 권한 안내 동의, 비교 테스트 집계 결과만 앱 비공개 설정에 저장합니다. 앱 데이터의 클라우드 백업과 기기 이전은 차단합니다.
- 일반 편의 앱으로 별도 접근성 안내와 명시적 동의를 제공합니다. Play 배포 전에는 접근성 및 카메라 포그라운드 서비스 정책 검토와 선언이 필요합니다.

## 빌드와 테스트

필요 환경: JDK 17 이상, Android SDK Platform 36, Build Tools 36.0.0. 최초 의존성 다운로드에는 인터넷이 필요합니다.

Windows PowerShell의 공식 검증 명령:

~~~powershell
$env:JAVA_HOME = 'JDK 경로'
$env:ANDROID_HOME = 'Android SDK 경로'
.\scripts\build.ps1
~~~

스크립트는 testDebugUnitTest lintDebug assembleDebug를 실행하고 버전별 APK를 dist/에 복사합니다. 디버그 키와 Android 설정은 .build-tools/에, Gradle 캐시는 임시 디렉터리의 eyeshorts-gradle/에 생성합니다. PC 환경 변수를 영구 변경하지 않습니다.

캐시가 준비된 상태에서 오프라인으로 검증:

~~~powershell
.\scripts\build.ps1 -Tasks @('testDebugUnitTest','lintDebug','assembleDebug','--offline')
~~~

USB 디버깅을 허용한 테스트 휴대폰에 설치:

~~~powershell
.\scripts\install.ps1
# 여러 기기가 연결된 경우
.\scripts\install.ps1 -Serial '기기 시리얼'
~~~

Android Studio에서 이 디렉터리를 프로젝트로 열 수 있습니다. 최초 실행 전 build.ps1로 로컬 SDK 경로와 개발용 키를 준비합니다. 디버그 키는 배포용으로 사용하지 않습니다. 소스 ZIP에는 키를 포함하지 않으므로 다른 PC에서 새 키로 빌드하면 기존 APK를 삭제한 뒤 설치해야 할 수 있습니다.

## 구성과 검증 기록

- GazeCamera.java, PreviewBus.java, CameraPreviewView.java: 카메라 분석과 메모리 내 미리보기.
- TrackingService.java: 카메라 서비스, 눈·입 입력과 단독 입 연습, 관찰 모드와 알림.
- ShortsAccessibilityService.java: 활성 쇼츠/릴스 확인과 최종 재확인 후 위/아래 스와이프 또는 중앙 탭.
- core/: 입력 분류, 보정, 얼굴 상태, 비교 집계 및 JVM 단위 테스트 대상.
- 변경 기록은 docs/CHANGELOG.md, 자동 검증과 실기기 미확인 항목은 docs/VALIDATION.md에 있습니다.

좌우 눈은 미러 미리보기 위치가 아닌 본인의 눈 기준입니다. [MediaPipe 공식 눈 연결 정의](https://github.com/google-ai-edge/mediapipe/blob/master/mediapipe/tasks/web/vision/face_landmarker/face_landmarks_connections.ts)에서 33/133은 오른쪽 눈, 362/263은 왼쪽 눈입니다. 카메라 측정의 눈 열림 값을 이 기준으로 정리했으며 기존 평균 시선·머리 위치 계산은 유지했습니다.

Instagram 재생기 판별에는 [InstaAddict 제작자의 공개 릴스 구현 설명](https://github.com/ssucipto/instaaddict#1-full-screen-reels--modern-ig-v446-compatibility)에서 확인한 `clips_viewer_view_pager`, `root_clips_layout`, `clips_viewer_container`만 추가했습니다. 이 자료는 화면 ID 선택의 근거이며 현재 사용자 기기에서의 호환성 검증을 대신하지 않습니다.

입 벌림은 기존 Face Landmarker의 입술 점(61/291, 13/14)으로 계산하며 별도 모델을 추가하지 않았습니다. 중앙 한 점의 짧은 터치는 [Android StrokeDescription의 단일 점 제스처](https://developer.android.com/reference/android/accessibilityservice/GestureDescription.StrokeDescription)로 보냅니다. [TeamYouTube의 쇼츠 탭 일시정지 안내](https://support.google.com/youtube/thread/445002770?hl=en&msgid=446250278)를 참고했으며, 두 앱의 현재 기기에서 실제 재생 전환은 별도 확인 대상입니다.

[Android 접근성 제스처](https://developer.android.com/guide/topics/ui/accessibility/service), [카메라 포그라운드 서비스](https://developer.android.com/develop/background-work/services/fgs/service-types#camera), [MediaPipe Face Landmarker](https://ai.google.dev/edge/mediapipe/solutions/vision/face_landmarker/android), [Google Play 접근성 정책](https://support.google.com/googleplay/android-developer/answer/10964491).
